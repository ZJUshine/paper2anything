# 卡片设计规范（你手写 post_cards/p<N>.html 时看这份）

正文配图**不是论文原图直出**，而是你亲手写的 HTML 卡片，`render_cards.py` 截成 PNG。
风格取向与 paper2html 一脉相承：**先立设计概念，再排版**，而不是往固定模板里填空。
区别只在载体——那边是桌面长页，这边是**手机上被拇指快速划过的 3:4 竖图**。

---

## 硬规格（不满足会被 render_cards.py 判 FAIL）

| 项 | 值 |
|---|---|
| 画布 | `1080 × 1440` CSS px（3:4 竖版），输出 2x = 2160×2880 |
| 安全边距 | 四周 ≥ 64px；底部 ≥ 96px（小红书 UI 会压住底部一条） |
| 卡片数 | **5–8 张**：每问至少一张（下限 5），上限 8 = 小红书图集 9 张 − 封面 1 张 |
| 文件名 | `p1.html … pN.html`，**严格按阅读顺序连号**（`p10` 排在 `p9` 后，按数字排不按字典序） |
| 图片引用 | 相对路径 `../figures/<文件名>`（卡片在 `post_cards/`、图在 `figures/`） |
| `<img>` | 必须有非空 `alt` |

骨架（直接抄这个起手）：

```html
<!doctype html>
<html lang="zh"><head><meta charset="utf-8"><style>
  html,body{margin:0;padding:0;width:1080px;height:1440px;}
  body{box-sizing:border-box;padding:80px 72px 96px;
       font-family:-apple-system,"PingFang SC","Noto Sans CJK SC",sans-serif;}
</style></head><body>
  <!-- 你的卡片内容 -->
</body></html>
```

**别在 `html`/`body` 上写 `overflow:hidden`。** 它不会让内容装得下，只会把装不下的部分
悄悄裁掉——截图里话说一半，你还以为没问题。留着让内容自然溢出，自检才能报给你。
（`render_cards.py` 量高度前会强行放开 `overflow`，所以写了也瞒不过它，只是你自己看截图时会被骗。）

---

## 字号下限：按"手机上一臂距离能读"定

卡片在手机上宽约 350pt，即 **1080px 画布被缩到约三分之一**。所以画布上的 45px ≈ 手机上的 15px。

| 角色 | 画布字号 | 说明 |
|---|---|---|
| 卡片主问题（Q 标题） | 56–72px | 一眼抓住，最多两行 |
| 正文/要点 | 36–44px | **绝对下限 32px**，再小手机上就废了 |
| 数字/指标强调 | 80–140px | 数据卡的主角，让数字自己说话 |
| 图注、脚注、来源 | 26–30px | 只放这一类真正次要的信息 |

行高 1.5–1.7；中文别用 `letter-spacing` 负值。

---

## 卡片文案 ≠ 正文文案：图里要比正文更详细

正文（`xhs_post.body`）受小红书 1000 字硬顶挤压，每问只有 100–160 字，是**被压缩过的版本**；
卡片没有这个上限，是**图集里真正承载细节的一层**。所以：

- **别把正文那段答案原样搬到卡上。** 卡片和正文逐字重复，等于读者划完整个图集什么新东西都没看到。
- 卡片文案的原料是 **`xhs_post_detailed.md` 里对应那一问的详细版**（Step 3a 用户精简前的长稿），
  以及 `parsed/` 里的原始数据——从长稿里挑正文塞不下的那部分：具体数据点、方法的关键步骤、
  实验设置（数据集/基线/指标）、边界条件与失败情形。正文里被砍掉的枚举（模型名清单、多组数值）尤其适合放这儿。
- 正文与卡片的分工：**正文负责让人看懂"这篇论文在干什么、值不值得看"，卡片负责让人看到"具体怎么做、数字是多少"。**
- 但**详细 ≠ 堆砖**：仍然一句一个信息点、有层级（小标题 / 要点列表 / 数字块），别写成一整坨段落。
  卡上的每个数字同样必须在 `parsed/` 里查得到出处，**不许为了"更详细"而编**。

文字总量按卡片形态分档（画布空间决定，不是硬性字符数——真正的裁判是 `render_cards.py` 的竖向溢出检查）：

| 卡片形态 | 文字总量 | 说明 |
|---|---|---|
| 纯排版卡（无图，如 Q1 / Q5 卡） | **180–260 字** | 空间全给文字，可以写到充实 |
| 带原图 / 表格的卡（如 Q3 / Q4 卡） | **100–150 字** | 主视觉占掉一半画布，文字做标注与解读 |
| 上限 | 约 **300 字** | 再多就**拆成两张卡**（见下节），不是缩字号、也不是硬塞 |

字号下限 32px 是不可让的底线：**永远先砍字，不许为了多塞几句把字号压到 32px 以下。**

## 整套卡片要像一套，而不是各画各的

在 `understanding.card_design` 里先定好一组设计 token（配色、字体、圆角、图框样式），
所有卡全部复用它。**统一的是外壳，变化的是内容形态**：

- 每张卡左上角固定位置放序号徽标，右下角固定放论文简称——翻图时有连续感。
- 底色、强调色、图框圆角、分割线粗细，每张必须完全一致。
- 卡片之间靠**内容形态**拉开差异：Q1 概览走大字标题、Q3 方法走框架原图、Q4 实验走数据表。

配色从 `understanding.cover_palette` 延续（封面同源），保证图集第一张到最后一张是一个调性。
参考浅色调：通用 `#F4F5F7`+`#2E86AB`、生物 `#EEF6F0`+`#2D8A5F`、物理数学 `#F1ECF8`+`#6A30C2`、
工程 `#FBF0EC`+`#D85A3C`、社科 `#F4EEF2`+`#8A5A78`、化学 `#EAF4F8`+`#0E86C0`。

## 卡片数量：五问是下限，不是上限

**五问是骨架、是下限**（每问至少一张卡）。图集上限 9 张、封面占 1 张，所以卡片可以做到 **8 张**——
**五问之外只有 3 张余量**，得花在最值钱的地方。超出的部分 `publish.py` 会**静默丢掉**
（`render_cards.py` 会先告警），所以别写第 9 张卡。

多出来的卡有两种来源：

1. **拆卡** —— 一问信息太多，单张装不下（或塞进去就得压字号），拆成连续几张。
   序号徽标写 `Q3 · 1/2`、`Q3 · 2/2`，让读者知道还在同一问里。
   **拆卡优先于压缩**：与其把 Q4 的六个数字挤成一张小字卡，不如拆成"主结果"+"消融"两张。
2. **扩展卡** —— 五问之外值得单独占一图的内容，徽标用 `＋`（不占 Q 序号）：

| 扩展卡 | 放什么 | 什么时候值得加 |
|---|---|---|
| 关键原图精读 | 一张论文核心图 + 你的逐处标注 | 框架图/主结果图信息量大，一张卡讲不完 |
| 更多实验结果 | 第二张结果表、消融、跨数据集对比 | 论文实验章节远超一张卡的容量 |
| 方法细节拆解 | 某个关键设计的单独展开 | 方法有一个真正巧妙的点，值得单独讲 |
| 局限与失败情形 | 论文自己承认的边界、失败案例 | 论文有明确 limitation 段落（**这一张最能建立可信度**） |
| 上手信息 | 代码/数据链接、复现要点、算力需求 | 论文开源、读者可能真的想用 |
| 一句话总结 | 全文一句话 + 关键词 | 图集用满 8 张时收个尾（余量紧，通常先让位给上面几类） |

**多少张合适：让内容决定，不要凑数。** 5 张（一问一张）本身就是完整的；6–8 张适合信息密集的论文。
**一张空洞的卡比少一张更伤完读率**——写不出新东西的卡就别加，别把一张卡的内容摊成三张。
**余量只有 3 张，所以要挑**：先问「这张能给读者什么正文和其他卡都没有的东西」，答不上来就不做。

## 五问各自适合的卡片形态（建议，不是模板）

下表是**每问的第一张卡**；一问拆多张时，后续卡按上一节的拆卡规则接着排。

| 问 | 问题 | 形态建议 | 主视觉 |
|---|---|---|---|
| Q1 | 论文的主要内容是什么？ | 大字一句话结论 + 2–3 个关键词胶囊 + 下方 2–3 行把结论展开 | 通常无图，靠排版 |
| Q2 | 论文试图解决什么问题？ | 左右/上下对比："现状痛点" vs "期望"，各带 1–2 条具体说明 | 痛点示意，或问题相关原图 |
| Q3 | 论文如何解决这个问题？ | 框架图打底 + 3 步流程标注，每步一句写清输入/输出 | **论文框架/方法总览原图** |
| Q4 | 论文做了哪些实验？ | 数据卡：大数字 + 对比条，或结果表截图；补一行实验设置（数据集/基线/指标） | **结果表 / 曲线原图** |
| Q5 | 论文有哪些启发？ | 3 条要点清单，每条一行 emoji + 一句展开 | 通常无图 |

没有合适原图的卡就**纯排版**，别硬塞一张糊图凑数——空着比塞垃圾好。
纯排版卡不等于字少：省下的图位用**内容**填（多一条要点、多一层展开），别靠放大字号占位。

## 嵌原图：边框贴着图，永远别拉变形

这几条是 paper2html `html-authoring.md` 的图片 CSS 铁律，在卡片里同样适用：

- **边框要贴住图本身**，不能框住一圈留白：别在定宽盒子上同时用 `width:100%` + `object-fit:contain`。二选一：
  - 铺满栏宽：`display:block; width:100%; height:auto;` + border
  - 限高居中：`display:inline-block; max-height:X; width:auto; height:auto;` + border，外层 `text-align:center`
- **绝不为了填满留白而钉死 `height`（或同时钉死 `width`+`height`）**——那是把图拉变形。
  最多定一个轴，另一轴让它自适应。留白用**内容**填（多写一条要点），不是把图抻大。
- **别放大小图**：渲染宽度超过原图自然宽度 1.5 倍就会糊（自检会软告警）。宁可缩小居中。
- 原图周围加 16–24px 内边距 + 浅色底，让白底论文图和卡片底色之间有过渡，不然图会"融"进背景。

多面板大图常被解析器从中间拆成两半、图例被裁——**务必先 `Read` 原图亲眼看过**再决定嵌不嵌。

## 嵌表格：截图保真，重排好看，按情况选

`parsed/tables_index.json` 每条同时给了两样东西：

- `image_path` — 表格截图，**保留原排版与公式，最保真**。列多、含公式、含多级表头时用它。
- `table_html` — MinerU 重建的 HTML 表格，**便于你重排成卡片风格的原生表格**（自己配色、加粗最优行、
  砍掉不必要的列）。列少、纯数字的结果表用它，效果远好过贴一张小字截图。

用 `table_html` 重排时：
- **砍列**。论文表七八列，卡片上放 3–4 列（方法名 + 1–2 个主指标 + 对比基线）就够，其余删掉。
- 最优行用强调色底 + 加粗，让读者一眼看到结论。
- 表格字号同正文下限 32px；数字用等宽数字（`font-variant-numeric:tabular-nums`）对齐。
- **别做横向滚动容器**——截图截不出滚动，超宽只会被切。列放不下就继续砍列。

无论用哪种，都**不许改动数字**。删列可以，改值不行。

## 设计语言（沿用 paper2html 的六种，挑一种或混搭）

| 设计语言 | 适合 | 特征 |
|---|---|---|
| 杂志编辑 | 叙事性强、概念新 | 大标题 + 衬线体，栏间留白，图文穿插 |
| 产品落地页 | 工具 / 系统 / 有 demo | 卖点卡片、强调"它能干什么" |
| 终端极客 | 底层系统 / 代码 / 算法 | 等宽字体、深色底、命令行感 |
| 学术海报 | 信息密集、结果多 | 分区色块、强标题带、一眼可扫 |
| 极简档案 | 经典 / 理论 / 文字为主 | 黑白灰、克制、排版即设计 |
| 数据仪表盘 | 指标多 / 对比表多 | 卡片网格、数字突出、表格挑大梁 |

**别复用上一篇论文的样式**——新一篇的卡片如果和上次做的长得一样，就是该重想的信号。

## 交付前自查

1. `render_cards.py` 四项硬指标全绿（图裂 / 图变形 / 竖向溢出 / 横向溢出）。
2. **逐张 `Read` PNG 亲眼看**：脚本只管渲染层缺陷，好不好看、字够不够大、留白匀不匀，只有你的眼睛能判断。
3. 全部连着看一遍：是不是一套？序号连贯吗？拆卡的 `Q3 · 1/2` 标对了吗？和 `cover.png` 是同一个调性吗？
4. 卡片上每个数字都能在 `parsed/` 里找到出处——**不许编**。
5. 把每张卡的文字和 `xhs_post.body` 对照一遍：**有没有哪张只是正文的逐字复述？**
   有就换成 `xhs_post_detailed.md` 里正文没放进去的那部分细节。
6. 卡片数在 5–8 之间，且**每问都至少有一张**；张数是内容撑出来的，不是凑的——
   有没有哪张删掉其实读者不会损失任何信息？有就删。
